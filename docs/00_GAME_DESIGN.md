# 游戏设计基线

## 1. 产品定位

一款俯视角 2D 像素牧场经营游戏。玩家在农场、田野和小屋之间活动，通过工具改造网格、播种和照料作物、采集环境资源、管理背包与体力，并在持续推进的时间中观察场景和 NPC 的变化、与场景物件及 NPC 交互。

首要目标不是扩充大量内容，而是完整复现参考成品的系统手感和可扩展结构：同一套物品/工具规则能够作用于农田、作物、树木、石头和掉落物；时间、场景切换、NPC 与世界状态通过事件解耦。

## 2. 设计支柱

1. **工具决定行动**：玩家选择工具或物品，目标格高亮并明确显示有效/无效，再通过按住蓄力、释放执行行动。
2. **网格规则一致**：翻地、浇水、播种、采集和掉落都使用同一坐标系统和目标解析流程。
3. **世界随时间演化**：作物只在满足条件时成长，天黑、午夜回家、体力恢复、NPC 日程都由统一时间源驱动。
4. **物品形成闭环**：环境对象产出掉落，掉落被吸附拾取，进入可堆叠背包，再通过键盘交换到 Toolbar 或 Itembar，成为下一次行动的输入。
5. **反馈先于内容数量**：光标、动画、音效、粒子、状态条和时钟必须让行动结果清楚可见。

## 3. 目标体验

- PC 键盘优先，输入全部由 InputMap action 驱动，并为后续手柄映射保留语义化 action。
- 四/八方向自由移动，角色视觉保持四方向朝向。
- Player 当前朝向决定交互方向；Toolbar 与 Itembar 的键盘选择共同决定唯一手持物。
- `Shift` 为慢走，默认移动为跑步，与参考成品一致。
- `use_held` 按住进行工具或种子蓄力、释放执行；`drop`（兼容 `drop_held`）将当前 `dropable` 物品一次一个放到面向格。选择、使用和丢下都不得依赖鼠标。
- Toolbar 只管理工具，Itembar 只管理可选择非工具物品；最近切换的 bar 成为唯一 active source，同一时间手中只能有一个 BackpackSlot。
- 切换时在 Player 头顶短暂显示对应 bar 并高亮选中格；HUD 常驻显示当前拿着的工具或物品。
- 背包支持打开/关闭、堆叠、方向焦点和按键交换。背包、Toolbar、Itembar 之间的交换只使用方向 action、确认/交换键和取消键，不支持点击或拖拽。

## 4. 首个完整版本的玩法范围

### 4.1 玩家与状态

- 移动、碰撞、朝向、走/跑/待机、持物和使用工具动画状态。
- 生命、体力、金币数据及 HUD；工具、种子、食物消耗体力或恢复体力。
- 体力或生命归零、以及到达深夜时，推进到下一天并回到小屋醒来。

### 4.2 物品与背包

- 类型：工具、种子、食物、普通材料、障碍物、植物/作物、家具预留。
- 初始工具：锄头、水壶、镰刀、采集篮、镐、斧。
- 物品堆叠上限、价值/价格字段、图标、世界表现、说明。
- 掉落物在感应到玩家后吸附移动并进入背包；满包时不得吞掉物品。
- Toolbar、Itembar 与 Inventory 是有类型边界的独立容器；工具只能进入 Toolbar，可选择的非工具物品进入 Itembar，普通存储留在 Inventory。

### 4.3 农田和工具

- 静态地块标签：可挖、道路、阻挡、可掉落等。
- 动态状态：已翻地、当天已浇水、地块上的 Item。
- 锄头翻地，水壶浇水；斧、镐、镰刀、篮子作用于匹配的可采集对象。
- 蓄力等级扩大作用范围；目标不足、背包物品不足或体力不足时安全降级，不产生部分损坏状态。
- 光标分为有效网格、有效对象、无效目标三种反馈。

### 4.4 种植、成长和收获

- 种子只能种在已翻地且没有占用对象的格子。
- 作物拥有多个生命阶段，每阶段定义出现日、图像/动画、生命值、可用工具和产出范围。
- 作物仅在前一天浇水时跨天成长。
- 成熟作物可用指定工具/篮子收获，产生物进入背包或生成掉落反馈。
- 树木、树桩、石头、草等复用“生命阶段 + 工具伤害 + 掉落表”模型。

### 4.5 时间、光照和场景

- 年、月、日、星期、小时、分钟；月份派生季节。
- 游戏时间按倍率推进，HUD 每 5 游戏分钟刷新。
- 农场、田野、小屋三个地图场景，通过传送口切换并淡入淡出。
- 地图切换时保留动态地块、生成物、NPC 与玩家状态。
- 一天结束后将玩家送回小屋，设置起床时间并恢复状态。
- 环境光随时段变化，室内和室外可使用不同光照配置。

### 4.6 世界对象、NPC 与基础交互

- 按区域/标签随机生成石头、杂草、树木、种子等对象，生成结果可保存且切场景不重置。
- 至少三个 NPC，各有按季节/星期过滤的日程事件；新游戏开始时 farm、field、beach 各有一个。
- NPC 可在同场景网格上寻路，并能通过传送口切换场景；阻挡格和障碍物不可穿过。
- 玩家可按 facing 方向与相邻的床、电视等场景物件以及 NPC 交互；基础线性对话使用可推进的对话气泡呈现。
- 首版只要求线性台词和确认/取消等简单二选一，不要求复杂对话树、好感或剧情系统。

### 4.7 表现

- 像素清晰的相机和贴图导入设置。
- 行走、工具使用、采集、破坏、拾取音效；环境音和背景音乐。
- 收获、碎石、草屑、树倒等短反馈。
- UI 不遮挡常用交互区域，所有文本在目标分辨率下完整显示。

## 5. 首日可玩闭环

最终整合验收应支持以下连续流程：

```text
小屋醒来
  -> 走到农场
  -> 用键盘从 Toolbar 选择锄头并翻地
  -> 用键盘从 Itembar 选择种子并播种
  -> 用键盘从 Toolbar 选择水壶并浇水
  -> 用斧/镐/镰刀清理资源并拾取掉落
  -> 打开背包，用方向焦点和交换键整理 Inventory/Toolbar/Itembar 并查看说明
  -> 观察时间与光照变化
  -> 推进到次日，确认已浇水作物成长
  -> 让作物成熟并收获
  -> 观察 NPC 按日程移动或换图
  -> 面对场景物件和 NPC 触发交互，完成一段可推进的气泡对话
  -> 保存、退出、读取，确认状态一致
```

## 6. 兼容参考但不虚构的边界

核心参考提交目前没有形成商店交易、复杂对话树、任务、婚恋、畜牧、烹饪、战斗或发布级存档 UI。首版只补充场景物件/NPC 的基础交互和线性对话气泡；以下功能不得塞入首版核心任务：

- 商店买卖和完整经济平衡。
- 多存档槽 UI、云存档。
- 条件分支和复杂 choice effect、好感、剧情和节日；睡眠确认等简单二选一不在此限制内。
- 动物饲养、钓鱼、采矿副本、战斗。
- 联机与移动端。

持久化存档虽然不是参考提交的完成能力，但为了让生成结果成为完整可继续开发的 Godot 游戏，首版包含单槽 JSON 存档；它必须保持独立，不能改变核心玩法规则。

## 7. 原创与资源边界

- 可以复现机制、系统职责和通用交互，不复制参考项目源代码表达。
- 默认不复制参考项目的角色、美术、音频、字体或 Unity 资源。
- 最初用清楚、统一的原创占位资源实现；正式资源必须记录来源、许可和生成成本。
- 任何外部素材进入 `assets/` 前，先在资源清单中记录作者/来源、许可证、是否修改和用途。
